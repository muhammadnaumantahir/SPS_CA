# Self-Programming Lifecycle

SPS-CA grows through governed evidence, not raw disagreement counts.

1. The user provides a goal, prompt, and optional code/file.
2. Cognitive reasoning and the Brain analyze the task.
3. Experience records outcomes and feedback.
4. Meta-learning evaluates recurring patterns and learning strategy.
5. Adaptation selects context-appropriate behavior without source mutation.
6. Evolution core performs the **SPS Growth Decision**.
7. A candidate may be reused, adapted, composed, improved, created, or deferred.
8. Verification & Validation Core tests the candidate in a sandbox.
9. Governance Core authorizes the change against Software DNA.
10. Execution Core applies only validated and authorized actions.
11. Trace/evidence returns to Experience for future learning.

## Key invariant

> **DISAGREEMENT ≠ CAPABILITY CREATION**

A single disagreement is evidence. Persistent evidence can expose a capability gap, but Layer 8 still reasons about capability relevance and chooses the appropriate growth action. Unsafe or insufficiently supported changes are deferred.

The implementation components are catalogued in `layers/architecture.py` and `docs/ARCHITECTURE.md`.
