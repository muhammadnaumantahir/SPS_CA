🎯 Getting Started

  1. Paste your code in the code editor (or click "Sample" for an example)
  2. Type a request — "Add input validation", "Fix the bug", "Generate tests"
  3. Click Send — SPS-CA processes through 10 layers with Brain reasoning
  4. Review the result — check the modified code and diff
  5. Agree or Disagree — if you disagree, SPS-CA creates a new capability for that pattern

🧠 The Brain (AI)

The Brain is a separate AI intelligence service — not a layer and not a capability. It provides:

  • Reasoning about your request and code context
  • Planning which capabilities to apply
  • Code generation and debugging
  • Failure analysis and strategy selection

By default, the Brain uses Ollama with qwen2.5-coder:7b. You can change the model in the settings.

🔄 Agree / Disagree Flow

Every SPS-CA response includes two buttons:

  • 👍 Agree — The result is good. SPS-CA records this as a success in experience.
  • 👎 Disagree — The result is not satisfactory. This triggers the Evolution Core (L8) to analyze the failure pattern and potentially create a new capability.

After 3+ disagreements on the same pattern, SPS-CA generates a new capability, validates it, and adds it to the registry.

📦 Capabilities

Capabilities are executable SPS skills, registered and versioned:

  • CAP-001 Simple Bug Detection
  • CAP-002 Syntax Error Fix
  • CAP-003 Unit Test Generation
  • CAP-004 Loop Optimization
  • CAP-005 Error Handling Pattern
  • CAP-006 Unused Variable Removal
  • CAP-007 Type Annotation Addition
  • CAP-008 Documentation Generation
  • CAP-009 Natural Language Code Modification

Generated capabilities (CAP-010+) are created through the Evolution Core when repeated failures are detected.
