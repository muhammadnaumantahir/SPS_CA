# Testing Architecture

Run the focused architecture test:

```bash
pytest layers/tests/test_architecture_manifest.py
```

The test verifies exactly ten canonical layers, exact canonical names, the authoritative sub-component vocabulary, the separate Brain boundary, and the absence of legacy layer directory names.

## Scenario suites

The original `evaluation/scenarios/growth_500.json` contains 500 canonical scenarios. The additional suite is generated by:

```bash
python scripts/generate_growth_500_additional.py
```

This creates `evaluation/scenarios/growth_500_additional.json` with another 500 executable scenarios (50 per canonical capability). The companion `test_additional_growth_scenarios.py` validates all 500 additional routing cases.

Together the two suites provide **1,000 scenario cases** for routing/intent regression. The live model-backed runner should be used to observe actual capability selection, reuse, adaptation, composition, improvement, creation, governance, validation, and execution evidence.

Then run the full suite:

```bash
python scripts/generate_growth_500_additional.py
pytest
```

The architecture manifest is the source of truth; tests should import it rather than duplicate layer names.
